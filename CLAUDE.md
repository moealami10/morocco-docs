What the project/website is supposed to accomplish Kaghit (intended domain: kaghit.com, not yet purchased — see Section 9) is a free, no-signup, French-language (Arabic in progress) website that helps Moroccan citizens with common administrative document needs. It has three layers:  Tools: instant document generators (fill a form → get a finished PDF immediately, entirely client-side) Guides: informational articles for documents that only the government can actually issue (Kaghit can't generate these, only explain how to get them and link to the official portal) Objectifs (goal wizard): goal-oriented pages that bundle the relevant tools/guides into an ordered checklist for a specific life situation ("I want to find a job," "I'm renewing my CIN")  Business intent: the site itself is not expected to be the primary income source. Its main strategic value is as a lead-generation funnel toward Moe's existing freelance Meta/Facebook ads-management service for Moroccan COD (cash-on-delivery) e-commerce sellers — every visitor is presumed to be exactly the kind of small business owner or individual that service targets. Secondary monetization is freemium document limits/micropayments. Display ads are deliberately deprioritized (see Section 6). Explicit strategic boundary: Kaghit is not trying to become a comprehensive "tell me your life goal and I'll handle everything" AI administrative assistant. This was proposed twice during this project (both times originating from ChatGPT-authored pitches Moe brought back for review) and rejected both times for the same reason: Morocco's government already built almost exactly that. Idarati.ma is the official national portal (600+ procedures, Loi 55-19) with an AI virtual assistant already integrated. Idarati X.0, launched February 2026, is a ministry-backed meta-application unifying 660+ procedures around a national digital identity/wallet, explicitly expanding toward personalized guided assistance. A private, solo-built site cannot out-compete a sovereign platform on "official guidance for dealing with the state." Kaghit's actual defensible position is being a narrow, free, instant-generation utility — not a comprehensive navigation layer. This boundary has been reaffirmed multiple times in this project and should be treated as a considered decision, not an oversight, if it comes up again.  2. Important technical decisions and why  Zero backend, ever, for the core tools. Deliberate, not a limitation being worked around. The tools handle sensitive data (CIN numbers, salaries, children's personal information) and the client-side-only architecture means none of it ever touches a server — this was independently identified as the site's single strongest trust asset by two separate outside reviews consulted during this project. sessionStorage, not localStorage, for both form-draft persistence and goal-wizard progress tracking. Deliberate: survives navigation within a tab (so users don't lose form progress switching pages) but auto-clears when the tab/browser closes — appropriate middle ground for sensitive data that shouldn't persist indefinitely on the device. Component duplication over an i18n library (e.g. react-i18next) for Arabic. Deliberate scope-control decision: a translation-key abstraction layer is more "correct" architecturally but adds real complexity that's a worse fit for a free-tier, quota-limited AI coding agent to get right in one pass. Plain parallel page files per language were judged more reliable to build correctly, even if less elegant, given the project's actual constraints. URL-based /ar/... routing, not a client-side toggle, for Arabic. Deliberate: the entire justification for building Arabic support was Arabic-language search demand data (see Section 15). A toggle that doesn't change the URL is invisible to Google — defeats the purpose. GitHub repo made public. Required to work around a real Vercel Hobby-plan restriction (see Section 9). Confirmed no secrets/API keys exist in the codebase before doing this (the architecture has none, by design, since there's no backend). Every Antigravity prompt opens with an explicit "site identity" line ("The site is called Kaghit, domain kaghit.com. Do not use any other name..."), repeated in every single prompt even after the name was established. This is a direct response to an observed failure mode: Antigravity carried a stale placeholder name ("Wraqi"/"Wraqi.ma") forward into files that a given prompt never even mentioned naming in (e.g. it resurfaced in the PDF disclaimer text generation logic several prompts after the name was supposedly already fixed everywhere). If Claude Code is generating its own multi-step instructions or working across a long session, it's worth being aware this kind of context-bleed is a real, observed risk with the coding agent this project has been built with — less relevant to Claude Code itself, but worth knowing why the existing prompts are written the way they are. Domain: kaghit.com chosen over kaghit.ma. .ma was seriously considered (stronger geo-trust signal, ANRT-verified) but .com was chosen for simplicity — no registrar identity verification step required. Not purchased yet either way. No display ads, deliberately, for now. Two reasons: (1) Vercel's free Hobby plan ToS technically restricts commercial use — ads/payments require upgrading to Pro ($20/mo); (2) researched Moroccan/French-language ad CPMs are low enough (\~$0.30–2 per 1,000 impressions) that meaningful ad revenue would require traffic in the hundreds of thousands of monthly pageviews, unrealistic near-term. Monetization priority order, from most to least likely to matter soon: (1) funnel to Moe's ad-management service, (2) freemium document limits/micropayments, (3) ads only once traffic genuinely justifies it, (4) B2B/white-label later, (5) a paid "bundle" tier for repeat business users.   7.
